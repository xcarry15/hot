开发选址助手生产部署与更新
============================

固定技术标识：

- 项目目录：`/www/wwwroot/hot.kfxz.cn`
- Node 服务：`127.0.0.1:3011`
- PM2 应用：`h2-hot2`，单实例
- SQLite：`db/custom.db`，Prisma 配置值为 `file:../db/custom.db`
- 备份目录：`/www/backup/h2-hot2`
- 正式站点：`https://hot.kfxz.cn`

生产环境要求：Node.js >= 20.9.0、npm >= 10、PM2、sqlite3、rsync、tar、curl；手工 ZIP 初始化另需 unzip。

## 一、日常更新

推荐路径：

```text
推送或合并 master
  → GitHub Actions: CI
  → CI 成功
  → Deploy production
  → 站点健康检查
```

自动部署由 `.github/workflows/deploy.yml` 调用 `scripts/deploy-production.sh`，依次执行：

1. 验证部署密钥、共享 `.env`、SQLite 和 release 中的完整 migration 集合。
2. 将代码解压到版本化 release 目录，执行 `npm ci`、`db:generate` 和生产构建；此时 current 版本保持不变。
3. 停止 PM2，普通部署用 SQLite `.backup` 创建可回滚备份，再执行 `db:migrate:deploy` 和 `db:optimize`。
4. 原子切换 `current` 软链，保留最近 5 个 release，启动单实例 `h2-hot2`。
5. 检查 `/api/health`、公开首页和 CSS 资源；普通部署失败会恢复数据库备份与旧 current，生产重置不自动回滚。

正常部署失败会在备份可用时恢复数据库与旧 current；生产重置不提供自动回滚。手动运行 `Deploy production` 不会补跑 CI，只应用于已经确认过的提交。

### 生产数据库重置

`reset_production=yes` 会跳过备份，直接删除生产 SQLite，再按当前 migration 和 seed 全新初始化。它只适用于明确放弃现有生产数据的情况，必须先获得明确授权。

普通部署允许当前发布包中尚未执行的新 migration 由 `db:migrate:deploy` 增量应用；发现未知或未完成的 migration 时，会在停止服务前拒绝继续。项目不维护旧 migration 历史的兼容升级路径。`releases/` 和 `current` 由部署脚本维护，不要手动删除 current 指向的目录。

## 二、首次部署或完全重建

此流程会重建 SQLite、`node_modules` 和 `.next`。`scripts/init-production.sh` 默认先备份已有数据库，但不会自动恢复业务数据。

### 1. 生成部署包

在 Windows 项目根目录双击：

```text
bat/run.bat
```

`bat/pack-deploy.ps1` 会在 `bat/` 生成 `h2-hot2-deploy-*.zip`。这是过滤后的生产部署包，不是完整源码备份；不包含 `.env`、`db/`、测试、文档、本地依赖和 Git 文件。

### 2. 准备生产配置

将 ZIP 上传到应用目录之外，例如：

```text
/www/wwwroot/h2-hot2-release.zip
```

确认 `/www/wwwroot/hot.kfxz.cn/.env` 存在：

```env
DATABASE_URL=file:../db/custom.db
API_TOKEN=<随机强令牌>
SETTINGS_ENCRYPTION_KEY=<长期不变的随机密钥>
NEXT_PUBLIC_SITE_URL=https://hot.kfxz.cn
```

`API_TOKEN` 和 `SETTINGS_ENCRYPTION_KEY` 可分别用 `openssl rand -hex 32` 生成。后者用于解密已保存的敏感设置，后续部署必须保持不变。

### 3. 验证并同步部署包

不要直接解压到应用目录，也不要使用 `rm -rf 项目目录/*`。在服务器执行：

```bash
(
  set -Eeuo pipefail

  APP=/www/wwwroot/hot.kfxz.cn
  ZIP=/www/wwwroot/h2-hot2-release.zip
  TMP="$(mktemp -d /tmp/h2-hot2-init.XXXXXX)"
  cleanup() { rm -rf -- "$TMP"; }
  trap cleanup EXIT

  test -s "$ZIP"
  test -s "$APP/.env"

  set +e
  unzip -q "$ZIP" -d "$TMP"
  UNZIP_CODE=$?
  set -e
  if [ "$UNZIP_CODE" -gt 1 ]; then
    echo "错误：ZIP 解压失败，状态码 $UNZIP_CODE"
    exit 1
  fi

  LOCK_FILE="$(find "$TMP" -maxdepth 4 -type f -name package-lock.json -print -quit)"
  test -n "$LOCK_FILE"
  RELEASE_ROOT="$(dirname "$LOCK_FILE")"
  test -f "$RELEASE_ROOT/package.json"
  test -f "$RELEASE_ROOT/scripts/init-production.sh"
  test -d "$RELEASE_ROOT/prisma/migrations"

  pm2 stop h2-hot2 >/dev/null 2>&1 || true
  pm2 delete h2-hot2 >/dev/null 2>&1 || true

  rsync -a --delete \
    --exclude='.env' \
    --exclude='.env.*' \
    --exclude='db/' \
    --exclude='node_modules/' \
    "$RELEASE_ROOT/" "$APP/"

  cd "$APP"
  ls -lh package.json package-lock.json scripts/init-production.sh
)
```

### 4. 初始化并启动

```bash
cd /www/wwwroot/hot.kfxz.cn
CONFIRM_RESET=YES bash scripts/init-production.sh
```

交互执行时也可运行 `bash scripts/init-production.sh`，再输入 `RESET`。脚本会备份旧数据库、清理旧运行产物、安装依赖、应用 migration、生成 Prisma Client、写入 seed、优化 SQLite、构建、启动 PM2，并检查本机与正式域名健康接口。

首次配置 PM2 开机启动时执行一次：

```bash
pm2 startup
# 执行上一条命令输出的系统命令后：
pm2 save
```

## 三、本地重新初始化

双击：

```text
bat/本地一键初始化.bat
```

输入 `RESET` 后，脚本会停止属于当前项目的 Node 进程，删除本地 SQLite 和 `.next`，应用 migration、写入 seed、优化数据库，并启动 `http://localhost:3011`。现有 `.env` 会保留。

依赖异常或 `package-lock.json` 变化时使用：

```text
bat/本地一键初始化.bat -RefreshDependencies
```

仅检查环境，不删除数据：

```text
bat/本地一键初始化.bat -CheckOnly
```

本地初始化不运行测试或生产构建。

## 四、检查与恢复

```bash
pm2 status
pm2 logs h2-hot2 --lines 100
curl --fail --silent --show-error http://127.0.0.1:3011/api/health
curl --fail --silent --show-error https://hot.kfxz.cn/api/health

cd /www/wwwroot/hot.kfxz.cn
npm run db:migrate:status
```

恢复已有项目进程：

```bash
cd /www/wwwroot/hot.kfxz.cn
pm2 delete h2-hot2 >/dev/null 2>&1 || true
pm2 start npm --name h2-hot2 -- start
pm2 save
```

只有修改 Nginx 配置时才执行：

```bash
nginx -t && nginx -s reload
```

普通应用更新不清理服务器全局 Nginx 缓存，也不 reload Nginx。页面出现旧 HTML、CSS 404 或无样式时，先核对 `bat/本项目的nginx.txt` 中 `/_next/` 和动态页面的反向代理/禁用缓存配置。

## 五、安全与数据规则

- 不提交或外传 `.env`、API Token、Webhook、SSH 私钥、SQLite、导出文件和部署包。
- 生产禁止使用 `prisma db push`、`db:danger:reset`；`db:seed` 只用于首次初始化或明确重建。
- migration、完全重建和危险数据清理前先确认备份文件有效。
- PM2 只运行一个 `h2-hot2` 实例，不使用 cluster 或 `-i max`。
- 业务数据清理使用后台 `设置 → 数据`，不要用删除 SQLite 代替。
