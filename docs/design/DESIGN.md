# 公开端视觉规范

本文件只描述公开端的稳定视觉方向，不记录产品行为、后台流程或实现状态。业务与架构以 `README.md` 和当前代码为准；实际颜色、间距和动效以 `src/app/globals.css` 及公共组件为准。

## 范围

- 适用于 `/`、`/news/[id]`、`/tools`、`/about` 及公开错误状态。
- 管理后台沿用自身的浅色/深色系统，不套用公开端视觉规则。
- 公共布局统一复用 `PublicPageShell`、`PublicHeader` 和 `PublicFooter`，内容最大宽度为 `1200px`。

## 核心原则

- 极简、扁平、直角、少装饰。
- 信息层级依靠字号、字重、留白和少量暖色强调，不依赖厚重卡片、阴影或大量分割线。
- 内容密度优先：移动端首屏尽快出现有效资讯或工具，避免空白大区块。
- 同类信息保持同一结构和交互，优先复用组件，不在页面内复制样式系统。

## 字体与层级

- 全站使用中文系统无衬线字体栈，以 Microsoft YaHei / PingFang SC 为主。
- 展示标题使用较粗字重和轻微负字距，正文保持清晰行高。
- 品牌暖色只用于关键短语、状态和主要反馈，不把整页染成强调色。
- 元数据保持紧凑，重复来源、重复状态和不影响判断的标签应合并或删除。

## 形状与表面

- 公开端按钮、输入框、标签、工具卡片和内容区使用方角。
- 文章列表优先透明背景或弱表面，不使用悬浮抬升和装饰性阴影。
- 分割线只用于区分真正不同的导航、时间段或页脚区域。
- 图标使用现有 Lucide 线性图标，保持统一尺寸和描边，不混入独立图标风格。

## 动效

- 入场只使用透明度淡入；标准时长 `220ms`，快速反馈 `140ms`。
- 悬停仅改变背景色、文字色或标记色，不移动、缩放或抬升元素。
- 不为列表、时间轴、按钮和卡片添加会改变布局的动画。
- 阅读进度条只使用水平 `scaleX`，不得触发布局重排。
- `prefers-reduced-motion` 下关闭入场动画并把过渡压缩到近即时。

## 响应式

- 移动端优先，触控元素保持可点击，导航使用独立移动行。
- 桌面端内容不超过 `1200px`；文字阅读区继续使用更窄的内部宽度。
- 网格通过减少列数折叠，不通过压缩字号或卡片内容维持列数。
- 标题应自然换行；只有明确要求的短标语允许单行显示。

## 维护规则

- 公共视觉方向变化时，先修改共享 token 或公共组件，再同步本文件。
- 页面局部实现不应反向扩充成本文件中的新“规范”。只有跨页面稳定复用的规则才记录在此。
- 不从外部品牌设计稿复制整套组件规范；只保留本项目实际使用且可在代码中找到的规则。
