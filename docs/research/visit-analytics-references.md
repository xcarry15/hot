# 访问统计重设计：开源项目参考

调研日期：2026-11-12。以下为 GitHub 项目的一手资料及对本项目的适配判断；不是对第三方统计口径的直接复刻。

## 参考

- [Umami：统计接口和维度](https://github.com/umami-software/umami/blob/master/packages/mcp/README.md)：提供核心指标与前期对比、按时间的流量序列，以及来源、地区、页面等分组。可借鉴「核心数字 → 趋势 → 分组排行」的信息层级及指标切换。
- [Umami：指标定义](https://github.com/umami-software/docs/blob/master/content/docs/metric-definitions.mdx)：对访客、访问、浏览、跳出和访问时长分别给出定义；其中标识、访问切分和本项目不同，不能把 Umami 的数值定义直接套用。
- [Umami：发布记录](https://github.com/umami-software/umami/releases)：提供对未结束时间段按前期已过时段对比和图表时间范围操作等设计。本项目若按完整自然日比较，应明确说明今天尚未结束，避免将这种比较误称为等时段对比。
- [Plausible：项目说明](https://github.com/plausible/analytics/blob/master/README.md)：强调聚合数据、单页主要信息及来源、目标等分析。适合本项目简洁的后台与隐私取向；不需要引入其数据库、追踪脚本或个人行为轨迹。

## 结合当前实现

- 网站访客为范围内 `visit_events.visitorId` 去重；访问为范围内按开始日归属的 `visit_sessions`；浏览为页面事件数。工具点击按日和工具汇总，资讯浏览和原文点击来自 Event 互动日汇总，不能与页面访问推算访客转化率。
- 优先使用当前可直接计算的数据：自定义日期与快捷范围、完整且可读的日趋势、访客/访问/页面浏览切换、渠道和地区占比、工具和资讯排行。可考虑同等完整日期数的前期比较；如果前期超出 365 天保留边界或涉及系统未开始采集的时段，应显示不可比较，不能把缺失历史当作零。
- 不采集页面路径、浏览器/设备或完整行为轨迹；不应虚构热门页面、设备占比、漏斗、新访客、真实停留时长和跳出率。`lastAt - startedAt` 只能表示记录到的首末活动间隔，不能等同阅读或停留时长；工具点击按日聚合也无法回推到单个访客或访问。
- 时间范围和分组需明确口径：访客范围内去重不等于每日访客相加；不同渠道/地区的访客可能重叠；跨日访问以开始日计数，页面浏览以发生日计数；资讯互动是 800 毫秒确认后计数。
